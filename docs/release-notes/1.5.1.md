3SF 1.5.1 rips and plays exactly as 1.5.0 does. It builds on new versions of the shared libraries. It also fixes three small problems with extracted games and loose archives.

3SF rips Nintendo 3DS sequenced music into a PSF-family format. The rips play with the game's DSP firmware on an emulated Teak DSP. 3SF comes with a ripper (`3sfrip`), a renderer (`3sfplay`), a foobar2000 component and an XMPlay plugin. The format is described in `docs/3sf.md`.

## Downloads

| `3sf-1.5.1-win-x64.zip` | `3sfrip` and `3sfplay` for 64-bit Windows |
| `foo_input_3sf-1.5.1.fb2k-component` | the foobar2000 component, for 64-bit and 32-bit foobar2000 v2 |
| `xmp-3sf-1.5.1.zip` | the XMPlay plugin, for XMPlay 3.8.2 or later |

The programs run on Windows 10 or later and require no runtime DLLs. To install the component, open the file with foobar2000 or add it under Preferences › Components. To install the XMPlay plugin, unzip `xmp-3sf-1.5.1.zip` and put `xmp-3sf.dll` in XMPlay's folder, or in a folder inside it. Then restart XMPlay. For macOS, see the README for instructions on building from source.

## New in 1.5.1

- **Extracted games copied from a Mac.** macOS writes a `._` file beside each file that it copies to a FAT or exFAT drive. `3sfrip` listed those files as part of the game's RomFS. A copied game then listed a `._` file as a sound archive, failed on it, and gave the real archive's library a longer name. `3sfrip` now leaves them out.
- **Group files past a folder that can't be opened.** For a loose `.bcsar`, `3sfrip` searches the folders around it for the game's group files. A folder that it couldn't open, such as `System Volume Information` at the root of an NTFS drive, ended the search. The group files past it weren't found, and their sequences didn't rip. `3sfrip` now passes over such a folder.
- **A clearer message.** An `exheader.bin` that is too short for an extended header now gets "is too short for an extended header", not "can't read".
- **The libraries.** 3SF now builds on ntdlib 3.6.0, with xsflib 1.10.0. The ripper and the players share more of their code with them. The rips stay byte for byte the same.

## Features

- **Ripping.** `3sfrip` rips a decrypted 3DS game (`.3ds`, `.cci`, `.cxi` or `.cia`, or an extracted game folder) or a sound archive (`.bcsar`, with a DSP firmware file) into a `.3sflib` and a `.mini3sf` for each sound, or only the music with `--bgm`. A game's rips contain the DSP firmware that the game uses. The firmware can be in a file or in the game's code. `3sfrip` finds the group files that a game keeps outside its sound archive. A piece that a game plays as several sequences gets one `.mini3sf`. `3sfrip` plays each sound to determine its length and fade tags. It also supports drag and drop.
- **Two rip modes.** Game mode runs the game's sound code. Game-mode rips play as the game does. Game mode requires a driver profile for the game. Pokémon X (Japan) has the only one so far. Archive mode plays a sound archive from any game with 3SF's model of the SDK's sound player.
- **Effects.** Game mode plays the reverb that Pokémon X starts in the field. Archive mode plays the effects that the games in its table put on the aux buses, including the DSP firmware's delay and reverb.
- **Starts.** Archive mode rips the listed sequences of known games as the game's code starts them, and their later states as files of their own.
- **Rendering.** `3sfplay` renders rips to WAV or FLAC at the DSP's native 32,728 Hz.
- **foobar2000.** The component plays `.3sf` and `.mini3sf` files using their length and fade tags. It supports tag editing, ReplayGain, endless playback and quick seeking. During playback, the component renders ahead. Seeking within the buffered audio is instant.
- **XMPlay.** The plugin plays `.3sf` and `.mini3sf` files using their length and fade tags. It supports endless playback. Like the component, it renders ahead during playback.
- **Speed.** On 64-bit Windows, the DSP firmware is translated into x86-64 code during playback. The 32-bit component and the XMPlay plugin interpret the firmware. Interpreting is slower. Use the 64-bit component if your foobar2000 and its other components allow it.

## Known limitations

- Seeking ahead of the audio buffer waits for rendering to reach the target. A long seek soon after a track starts can still be slow.
- Game mode only has a profile for Pokémon X (Japan). Other games rip in archive mode. Archive mode's model comes from Pokémon X. A game with another version of the sound library may play differently from the console.
- Only sequences are ripped. Use tools such as vgmstream for BCSTM and AAC streams. Wave sounds are skipped. So are sequences whose data lies outside the sound archive and its group files, or in a group file that `3sfrip` can't find.
- Archive mode plays effects only for the games and archives in its table. Another release or build of them gets none until someone reads its code. A loose `.bcsar` of another game and the other games get none either.
- Some games pick their effects for each scene or stage. A rip plays every sound with the effects that the game picks most often. Ocarina of Time 3D, Majora's Mask 3D, Island Tour, Star Rush and Super Mario 3D Land pick them that way.
- In one of its modes, WarioWare Gold also puts a pitch shifter on bus A. The rips leave it out.
- A game's code can change a sequence while it plays, such as its tempo or the volume of its tracks. A rip plays the start that the game gives the sequence, and the listed later states. Other changes aren't ripped.
- `3sfrip` finds a piece of several sequences only by the labels that Mighty Gunvolt Burst gives its sequences. In another game, each of a piece's sequences rips alone.
- The output is stereo.
