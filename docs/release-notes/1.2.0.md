3SF 1.2.0 finds the music in any game, gives better lengths, skips silent sounds, and adds a tag for sequences that wait for the game.

3SF rips Nintendo 3DS sequenced music into a PSF-family format, and plays it with the game's DSP firmware on an emulated Teak DSP. It comes with a ripper (`3sfrip`), a renderer (`3sfplay`) and a foobar2000 component. The format is described in `docs/3sf.md`.

The programs run on Windows 10 or later and need no runtime DLLs. To install the component, open the file with foobar2000, or add it under Preferences › Components. For other systems, see the README for instructions on building from source.

## New in 1.2.0

- **Sequences that wait for the game.** Some sequences play nothing until the game sets one of their variables. In archive mode, `3sfrip --var N=V` sets variable N to V before each sequence starts, and writes it in the new `3sf_var` tag. Players apply the tag when they start the sequence. Variables 0 to 15 belong to the sound's player, and 16 to 31 are the global ones. N and V can be hex (`0x...`), and `--var` can be repeated. The foobar2000 component keeps the tag when you edit or remove tags.

## Fixed in 1.2.0

- **Music in any game.** `3sfrip --bgm` rips the music of any game. It used to take only the sounds whose labels start with `SEQ_BGM`, as Pokemon X's do, so it found nothing in games that label their music differently. It now takes the sounds whose labels mark them as background music, jingles or fanfares, whatever comes before those words, and the sequences with 3 tracks or more and 50 notes or more, which finds the music that a game's labels don't mark, and the music in sound archives without labels. With `--only`, it takes the music whose label matches.
- **Lengths.** The length analysis follows the music rather than the first track alone. A track that only polls or counts a variable no longer makes loops. A piece whose first track polls the game while other tracks play it used to get a few milliseconds and the fade. It now gets two loops of the piece. A track that waits for the game no longer keeps later tracks from looping. Loops that go round before the first sound, or without a sound, don't count. A sequence whose tracks only hold notes on looping waves loops once the waves have looped twice. It used to play to the 600-second limit. So did a sequence that loops for ever inside a subroutine that nothing can leave, and one whose one moving track only changes the volume or pitch of a note that never ends. Both now loop. So does a later track that plays a note and then counts time in an inner loop. A sequence that ends now ends half a second after its last audible sound. It used to end when its last note fell silent. `docs/3sf.md` has the rules.
- **Silent sounds are skipped.** `3sfrip` lists and skips the sounds that make no sound. The sound library mutes a sound whose volume in the sound archive is 0, and the length analysis finds the sequences that never sound. They used to be ripped as silence.
- **Velocities above 127.** In archive mode, a velocity range can raise a note above velocity 127. On an instrument with one region for every velocity, such a note now plays, as in the game. It used to play nothing.
- **Voices beyond the DSP's capacity.** As in the game, archive mode plays only the voices whose DSP cycles fit in a frame. It drops the lowest-priority ones that don't. It takes many voices pitched far up at once to reach the limit.
- **ADPCM loops.** Where a wave's loop starts in the middle of an ADPCM frame, archive mode starts the loop at that sample. The game does the same. It used to start up to 13 samples earlier, at the start of the frame.
- **Numbers in tags.** The `length`, `fade` and `volume` tags read the same under every locale. A host program could set a locale that writes decimals with a comma. Every rip then played at the default length, and a volume of 0.5 read as 0. Like `length` and `fade`, the `volume` tag now also takes a comma before decimals.
- **Long WAV files.** `3sfplay` refuses a length that a WAV file can't hold, a little over 9 hours, before it renders anything. It used to refuse only after rendering. FLAC files have no such limit.
- **Inputs whose names differ only in case.** On Windows and macOS, `3sfrip` ripped two inputs such as `Game.3ds` and `game.cia` into one folder, and the second rip's files replaced the first's. The second rip's files now get different names.
- **Clearer messages.** `3sfrip` names Wii (`.brsar`) and DS (`.sdat`) sound archives as such. It used to say they weren't 3DS images. It also says when `--firmware` names a folder, when a folder isn't an extracted game, and which block a file in a sound archive lacks. That last message used to be "map::at". A file that's cut short says so.
- **Linked folders in extracted games.** `3sfrip` follows the folders in an extracted game's `romfs` that are symbolic links, and passes over a broken link. A broken link used to stop the rip.

## Features

- **Ripping.** `3sfrip` rips a decrypted 3DS game (`.3ds`, `.cci`, `.cxi` or `.cia`, or an extracted game folder) or a sound archive (`.bcsar`, with a DSP firmware file) into a `.3sflib` and a `.mini3sf` for each sound, or only the music with `--bgm`. A game's rips carry the DSP firmware the game uses, whether it's in a file or in the game's code. `3sfrip` plays each sound to determine its length and fade tags. It also supports drag and drop.
- **Two rip modes.** Game mode runs the game's sound code, so the rips play as the game does. It needs a driver profile for the game, and Pokemon X (Japan) has the only one so far. Archive mode plays a sound archive from any game with 3SF's model of the SDK's sound player.
- **Rendering.** `3sfplay` renders rips to WAV or FLAC at the DSP's native 32,728 Hz.
- **foobar2000.** The component plays `.3sf` and `.mini3sf` files using their length and fade tags. It supports tag editing, ReplayGain, endless playback and quick seeking, and renders ahead during playback, so that seeking within the buffered audio is instant.
- **Speed.** On 64-bit Windows, the DSP firmware is translated into x86-64 code as it plays. The 32-bit programs interpret the firmware, which is slower, so use the 64-bit component if your foobar2000 and its other components allow it.

## Known limitations

- Seeking ahead of the audio buffer waits for rendering to reach the target, so a long seek soon after a track starts can still be slow.
- Game mode only has a profile for Pokemon X (Japan). Other games rip in archive mode, whose model comes from Pokemon X, so a game with another version of the sound library may play differently from the console.
- Only sequences are ripped. Use tools such as vgmstream for BCSTM and AAC streams. Wave sounds and sequences with data outside the sound archive are skipped.
- The output is stereo.
