3SF 1.2.1 fixes a bug in the translated DSP code and keeps characters outside ASCII in rips' file names. The source now builds on two libraries, xsflib and ntdlib.

3SF rips Nintendo 3DS sequenced music into a PSF-family format. The rips play with the game's DSP firmware on an emulated Teak DSP. 3SF comes with a ripper (`3sfrip`), a renderer (`3sfplay`) and a foobar2000 component. The format is described in `docs/3sf.md`.

## Downloads

| File | Contents |
|---|---|

| `foo_input_3sf-1.2.1.fb2k-component` | the foobar2000 component, for 64-bit and 32-bit foobar2000 v2 |

The programs run on Windows 10 or later and require no runtime DLLs. To install the component, open the file with foobar2000 or add it under Preferences › Components. For macOS, see the README for instructions on building from source.

## Fixed in 1.2.1

- **Translated DSP code.** On x86-64 systems, such as 64-bit Windows, 3SF translates the DSP firmware into x86-64 code during playback. On other systems, 3SF interprets the firmware. At the end of a repeated block of firmware code, the interpreter advances the loop to the next pass before the block's last instruction runs. When that instruction saved the loop counter (`push lc`), the translated code saved the counter as it was before the loop advanced. The interpreter now runs that instruction on x86-64 too. Only firmware with such an instruction is affected.
- **Characters outside ASCII in file names.** `3sfrip` keeps printable characters outside ASCII in the names of the files it writes. For example, `--game Café` now gives `Café.3sflib`. It used to give `Caf__.3sflib`. Control characters and bytes that aren't valid UTF-8 still become `_`. Names in ASCII stay the same.

## Changed in 1.2.1

- **Building from source.** 3SF now builds on two libraries: xsflib, for players and rippers of the PSF family, and ntdlib, for the hardware and formats of Nintendo's consoles. The repository holds them as git submodules. Clone it with `git clone --recursive`, or run `git submodule update --init --recursive` in a clone. The source code archives on the Releases page don't include the submodules. The CMake presets now require CMake 3.23 or later.
- **Cut-short program data.** A file whose compressed program is cut short gives the message "truncated program data". It used to give "corrupt program data" when the data before the cut unpacked to a whole number of MiB.
- **Unusual files in extracted games.** In an extracted game folder, a folder named `exefs/code.bin` now gives the message "code.bin is truncated or not valid BLZ". `3sfrip` reads a pipe named like one of the game's files as that file. If a file shrinks while `3sfrip` reads it, `3sfrip` goes on with the shorter data. In all three cases, `3sfrip` used to stop with "can't read" and the file's path.

## Features

- **Ripping.** `3sfrip` rips a decrypted 3DS game (`.3ds`, `.cci`, `.cxi` or `.cia`, or an extracted game folder) or a sound archive (`.bcsar`, with a DSP firmware file) into a `.3sflib` and a `.mini3sf` for each sound, or only the music with `--bgm`. A game's rips contain the DSP firmware that the game uses. The firmware can be in a file or in the game's code. `3sfrip` plays each sound to determine its length and fade tags. It also supports drag and drop.
- **Two rip modes.** Game mode runs the game's sound code. Game-mode rips play as the game does. Game mode requires a driver profile for the game. Pokemon X (Japan) has the only one so far. Archive mode plays a sound archive from any game with 3SF's model of the SDK's sound player.
- **Rendering.** `3sfplay` renders rips to WAV or FLAC at the DSP's native 32,728 Hz.
- **foobar2000.** The component plays `.3sf` and `.mini3sf` files using their length and fade tags. It supports tag editing, ReplayGain, endless playback and quick seeking. During playback, the component renders ahead. Seeking within the buffered audio is instant.
- **Speed.** On 64-bit Windows, the DSP firmware is translated into x86-64 code during playback. The 32-bit component interprets the firmware. Interpreting is slower. Use the 64-bit component if your foobar2000 and its other components allow it.

## Known limitations

- Seeking ahead of the audio buffer waits for rendering to reach the target. A long seek soon after a track starts can still be slow.
- Game mode only has a profile for Pokemon X (Japan). Other games rip in archive mode. Archive mode's model comes from Pokemon X. A game with another version of the sound library may play differently from the console.
- Only sequences are ripped. Use tools such as vgmstream for BCSTM and AAC streams. Wave sounds and sequences with data outside the sound archive are skipped.
- The output is stereo.
